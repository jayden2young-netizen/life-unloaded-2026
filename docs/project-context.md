# 项目开发约束

## 文档与事实优先级

- 当前实现事实以现场 Git、版本常量、生成数据和实际测试为准；任何摘要都不能替代现场核验。
- `AGENT_HANDOVER.md` 记录当前接手状态与下一步边界；`progress.md` 是按时间倒序的历史流水，旧条目不构成当前授权。
- `roadmap/00-总体策略.md` 与当前版本 roadmap 共同定义已批准的版本顺序和实施边界；标为“占位”的 roadmap 不授权实现。
- `_bmad-output/`、研究档案和 `docs/Claude+Fable+5_Third_party_analysis/` 提供证据或历史建议，不是当前可执行 roadmap；与当前实现或正式 roadmap 冲突时不得据此改动项目。

## 数据与版本

- 玩家内容只改 `content/zh-CN/` 与 `tools/generate-v5-data.mjs`，`data.json` 仅由生成器写出。
- 同一发布中的 `index.html`、`game.js`、生成器、`data.json`、README 与测试版本断言必须一致。
- 生成器连续运行两次，第二次不得产生差异。

## 状态所有权速查

| 事实 | 唯一来源与合法写入 | 其他系统的边界 |
|---|---|---|
| 学历、申请、报到、教育地区与教育证据 | `education`；教育 transition／申请结算 | 就业只读取，并同步实际已经取得的 `entryCredential`，不能反向补学历 |
| 岗位、合同、就业状态、职业层级与职业收入 | `employment`；就业 transition／招聘结算 | 家庭、住房、债务和晚年只读取，不创建平行职业事实 |
| 父母、伴侣、子女与家庭关系 | `people` 与 `relationships`；人物与关系命令 | `childCount` 等派生值不能创建人物；social 不另存家庭人物 |
| 持续社会人物 | `people[*].social` 与 `social` 两个终身槽位 | `relationships.network` 只表示认识面，不等于具体朋友或办事能力 |
| 当前主要住处 | `housing`；只通过 `transitionHousing`／`socialCoResidence` | `finance.housingDisposition` 只保存不可逆处置历史，不能覆盖当前住房 |
| 逐笔债务 | `finance.liabilities`；债务专用命令 | 第二笔债务不重启同名 episode，也不清空第一次危机历史 |
| 习惯类型、阶段、风险与恢复年限 | `habits`；习惯事件结算 | 健康和压力只接收明确效果，不能凭文案推导诊断或治疗完成 |
| 卡牌介入 | 当前选择的 `cardInteraction` 与合法 patch | 只能改变当前选择的门槛、代价、风险或结果，不能单独补造人生事实 |
| Episode 与延迟回响 | `episodes`、`scheduledConsequences` 与对应选择 memory key | 刷新、恢复和迁移不得重复结算；人物或资格失效时按既有失效语义收束 |
| 存档与版本恢复 | 当前 Schema 默认值、normalize／merge 与迁移入口 | 不通过玩家文案或 UI 标签回写事实；Schema 变化必须单独批准 |

## 事件簇

- 每阶段直接显示包含情况、提问和选项的选择卡；选择后单独显示结果卡并确认，但阶段完成前不增加年龄。旧存档若停在重复的情况卡，只折叠该情况卡，不改已结算结果。
- 每阶段最多一次关键选择；短期簇最长五年，达到截止年龄必须播放明确结尾。
- 同时最多两个事件簇，同 lane 不并行；人物和单位在启动时绑定。
- 绑定人物、单位或资格失效时，用具体物件和事实收尾，不使用泛化的“状态改变”。
- 职业、婚姻、育儿、慢性病和恢复期是长期状态，不组成几十年活动链。
- 卡牌 `explanation` 与 `resultSuffix` 都可以省略；卡名足以说明介入时不复述选项，只有增加新的可观察事实时才保留后缀。

## 内容与研究

- 任何玩家可见中文的写作、改写或审阅开始前，必须完整阅读根目录 `CopyWriting_Guideline.md` 和本文。
- 制度、法律和医学规则以A级可靠资料校正；媒体用于常见矛盾，论坛和社交媒体只提供生活细节灵感。
- 不复制可识别私人经历，不把离奇个案写成普遍规律，不把当前政策永久写死在远期年代。
- 普通饮酒、游戏、购物、用药、远程工作或关系摩擦不能自动判为危机。

## 晚年生活

- `later.retirement` 只记录工作转段，不代表年龄、待遇资格或全部晚年身份；项目当前没有可信的养老金资格状态。
- 只有声明 `recurrence` 的普通 beat 可以复发：同句至少间隔 8 年、同组至少间隔 3 年，并读取 `timeline` 而不是清空 `usedEvents`。选择、后果、事件簇和不可逆事实继续严格一次性。
- 晚年内容可读取既有住房、人物、网络、孤独和本地联系；住房搬迁与适配由统一住房入口写入，具体 social 人物只由 v0.6.10 的显式事件建立或更新。

## 住房与居住选择

- `housing` 是当前主要住处及其稀疏历史的唯一事实源；内容只能通过 `transitionHousing` 写入，财务、教育、就业、迁移、伴侣、债务和晚年不得直接改 `housing.*`。
- 普通住房选择最多三次且类型不重复；只有真实债务使当前住房从可维持跌到不成立时，允许一次 `debtRelief` 第四次。自动宿舍、按揭结清和事实清理不消费选择预算。
- 地区锚点只在签约时确定租住或购房口径，`housing.value` 成交后固定；本项目不做年度房价、第二套房、装修或房地产经营模拟。
- 匿名室友和邻里不进入 `coResidentRefs`。只有通过 `socialCoResidence` 的在世、当地、关系未结束 social 人物可以成为一位具体同住人；强制 `arrangement:'shared'`、`costShare:'self'`，并继续消耗三次普通住房选择预算。临时落脚用 `residenceOnly:true` 保留产权与按揭；人物失效后引用清理，合法住处可退化为匿名 shared，不自动驱逐玩家。

## 社会交往与持续关系

- `social.primaryPersonId` 与 `social.secondaryPersonId` 是两个终身槽位；人物保存在 `people`，关系结束、搬远或转为伴侣都不释放名额。social 人物只保存称呼、来源、认识年龄、关系性质、远近、关键转折和已经发生的支持表现，不模拟职业、收入、房产、性格、日程或家庭。
- `relationships.network` 只表示认识面；`capabilities.network` 仍是办事与职业关系能力，`mobility.localTies`／`chineseCommunityTies`／`belonging` 继续由迁移事实拥有，`pressures.loneliness` 只表示未得到需要的连接或持续排斥压力。
- 主动独处从最近一次 `social:intent:solitude`／`social:intent:connect` 选择派生，不保存人格分数，不因拒绝活动自动增加孤独。结局可以读取临时 `socialEndingSignal`，但不得用它控制资格、随机或奖励。
- social 的不确定结果只允许最多三个显式创作的稳定变体；刷新、导入和恢复不得重抽。延迟回响必须绑定原人物；人物死亡、关系 ended 或槽位失配后该回响失效。
- 朋友转约会只进入既有 `dating`；referral 只创建就业入口；朋友合住仍走住房事务；危机支持不得清债、治病、结束长期照护或凭空生成永久住房。任何桥接都不得绕过原系统硬条件。

## 验证边界

- 先验证验收器与当前数据结构一致，再判断实现是否失败。
- 面向人的统一入口是根目录 `smoke.js`：无参数运行 `core`，`--fast` 运行全部脚本语法检查，`--full` 才运行发布档；底层 profile 仍由 `tests/run-checks.cjs` 维护。
- `--changed` 只自动处理证据明确的路径；`game.js`、生成器等多领域文件必须用 `--scope` 声明影响范围。
- 一个版本不自动对应一个新 smoke；状态和可达性优先进入快速合同，领域分支进入按需 regression。
- 每个版本做静态契约、定向成功／失败／退出／失效结尾与一次真实浏览器核心路径。
- 涉及卡片或抽屉时检查 360×773、360×640、320×568；控制台错误为0。
- 不运行批量人生模拟；完成标准满足后停止。
